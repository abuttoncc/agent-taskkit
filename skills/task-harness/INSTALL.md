# 安装一次，用自然语言交代任务

Task Harness 是一个 Skill，包含工作区约定、任务框架、场景卡、起始模板和 Python 辅助脚本。Agent 读这些材料并运行脚本；用户不需要逐个安装资源或学习命令。

## 现在怎么安装

项目名是 TaskKit，安装后的 Skill 名仍为 `task-harness`。

公开入口：[GitHub 仓库](https://github.com/abuttoncc/agent-taskkit) · [版本下载](https://github.com/abuttoncc/agent-taskkit/releases)。

也可以直接把下面这段交给你的 Agent：

> 请从 https://github.com/abuttoncc/agent-taskkit/tree/v0.4.0/skills/task-harness 安装 task-harness 到你当前运行时的用户级技能目录。先读安装说明，完成后确认你能发现这个 Skill，并列出当前可用模板。

把本技能 ZIP 附给支持文件读写和本地命令的 Agent，或给它 ZIP 的本地路径，再说：

> 请把这个 task-harness 技能包安装到你当前运行时的用户级技能目录，让它在其他项目中也可用。按包内安装说明完成安装，并确认你能发现这个 Skill。不要把我的当前项目变成技能安装目录。

“全局”指当前用户、当前 Agent 环境的用户级安装；不同客户端和不同机器可能需要分别安装。普通聊天窗口若不能访问文件系统或执行 Python，不能仅凭这段提示词完成安装。

安装 Agent：先查看包内容并读 SKILL.md 与 references/operations.md，识别当前运行时支持的用户级位置，再执行安装。ZIP 解压不得越出目标目录或通过符号链接写到外部。Python 缺失或客户端不支持 Skill 时准确报告，不冒称安装成功。

## 装好以后怎么说

- “先给这个工作区建立统一秩序，保留已有规则，任务按需建目录。”
- “用 task-harness 开始这项方案设计，记录目标、完成条件和交接。”
- “看看这个工作区有哪些任务、下一步是什么。”

- “用 task-harness 帮我验证这个 API，文档在这里，重点看它是否返回我要的数据。”
- “研究这家公司，重点看盈利质量和现金流，保存来源与报告。”
- “分析这次财报的变化，区分事实、推断和缺失信息。”
- “比较这几家公司的增长和利润率，先统一口径。”
- “继续上次的 API 测试。”
- “帮我检查这个任务还有哪些没完成。”
- “task-harness 目前有哪些模板？”
- “把 task-harness 更新到我提供的新版本。”

第一次可以明确提到技能名；后续是否自动匹配由宿主 Agent 决定。Agent 负责选资源、填任务定义、运行脚本与解释结果。只有必要信息缺失时才询问你。

当前包含工作区初始化、通用任务、任务总览与交接检查，以及通用验证、API 测试，以及金融研究的公司研究、财报分析和同业比较。视频制作由其他工具承接，不在本包实现。

## 发布者怎么分发

当前产物是可单独分发的 Skill ZIP。可把经过审查的固定版本 ZIP 放在自己的公开仓库 Release 或下载页；页面只需说明用途、下载入口、上述安装提示词和一句使用示例。安装提示词中的附件/来源必须是真实包，不发布未替换的示例网址。

面向有插件目录的客户端，可进一步将同一个 Skill 包装进插件，让用户点击安装。插件负责分发和宿主接入，Skill 继续负责任务方法与资源选择。

资源统一登记在 catalog.json。目前全部随包提供，支持离线读取；在线目录与按需下载尚未实现。以后增加资源仍可保留一个用户入口，但新增条目必须包含真实的流程、模板或脚本，不能只改目录就宣称已支持。
