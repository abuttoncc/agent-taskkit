# 固定四席

多源核对、复杂推理，或做完要留下协作复盘时用。简单问答、单次修改走通用任务，不建这个模式。

来源规则见 [外部调研](external.md)。公司、财报、同业比较仍用 finance-research。

## 四席

席位写在 request 里，顺序固定，done 时检查器核对：

| 席 | 只做这一倾向 | 何时继续 | 何时停止 |
| --- | --- | --- | --- |
| leader | 分发、综合，唯一撰写给用户的交付 | 还有未核对的问题或冲突 | 材料够用，开始写最终交付 |
| search | 仓库外的现行事实 | 还缺来源或来源互相冲突 | leader 开始收口 |
| analysis | 对照仓库、架构和风险 | 实现或风险还没写清 | 同上 |
| structure | 输出结构，以及现在能不能停 | 交付还缺完成条件要求的部分 | 同上 |

四席是任务里的固定分工，不是对话现场新造的代理。名字只用这四个。工具用当前环境已经有的搜索、读文件、代码和数据技能。leader 不向其他席授权工具，也不能关掉别人的工具。

## 顺序

1. 串行启动。leader 写清要核的问题。
2. 并行收集。search、analysis 和 leader 自己的核对同时做。发出分工之后，leader 立刻做自己的那份。派工只执行 [宿主派工](hosts.md) 里认宿主命中的那一节。
3. 同步。看已经回来的材料。够了就停，不够再补一轮。
4. 串行核对。数字、原话和「现在怎样」打开原文。外部事实标成「有」时，链接写入 sources.md。
5. 串行收口。只有 leader 写最终交付。内部过程不代替交付。

纯生成、材料已经够的任务，同步一轮后就进入收口，不再多等。

## 复盘和自进化

done 前写 `outputs/workflow.md`，用这四个二级标题，每节都有内容：

```text
## 并行
## 串行
## 谁在等
## 停止
```

每节写这次真实发生的事：谁同时在做、哪些步骤必须先后、谁在等谁的时候另一边做了什么、为什么可以停。检查器只确认四节非空，不判断写得对不对。

若有一句下次还能用的做法，另写 `evolve/candidate.md`：

```text
证据：outputs/workflow.md
建议：一句做法
```

然后运行：

```sh
python3 TH/scripts/harness.py evolve --root INSTANCE --topic TOPIC
```

脚本只在任务已经干净地 done、workflow 已被这份交接绑定、建议不是空话时，把这一句追加到工作区 `playbooks.local/inbox.md`。同一句再次出现，记为 ready。它不修改公共 Skill，也不改已安装的包。要让公共包改变，把 ready 的那一句送进 TaskKit 仓库，单独审查后再发版。
