# 工作区秩序

用户要建立工作区、安排新任务或接续旧任务时读本页。先确定归属，再选择流程，最后才建目录。

## 先读入口，不扫描整台机器

先读当前项目生效的 AGENTS.md/CLAUDE.md 与工作区入口，明确可写范围、现有任务位置、成果位置和保留规则。不要把某个项目的规则写到用户 home 或共享父目录，影响其他项目。只在当前获授权工作区查看任务总览；相关个人资产按已登记索引定点读，不因目录可见就跨用户查找。

公共 Skill 存放通用流程和脚本；工作区约定、个人偏好、任务和材料归用户所有。实例初始化只生成一次，后续升级中央包不重写这些文件。运行时发现入口指向已有规则，不再复制一份长期维护的规则。

## 判断落点

| 情况 | 动作 |
|---|---|
| 简单解释、一次查证、小修改 | 直接完成；调用工具本身不是建档理由 |
| 已有任务的补充、修订、下一阶段 | 在原任务继续，必要时补文件；换日、换工具、换会话不新建 |
| 新的独立目标，有不同交付与完成条件 | 建新任务；有关联时在 request 中引用原任务 |
| 暂时探索，还不能确定任务 | 用项目既有 tmp/或日期工作区；结论值得保留时归入正式任务并记来源 |
| 已有成熟目录与任务入口 | 沿用现有路径和规则；借用本 Skill 框架，不搬家或强制转换旧档案 |

优先级是用户指定路径、当前任务、工作区约定，然后才是默认位置。已有 TaskKit 实例用 tasks 看总览，按目标、对象和交付判断是否续做；不要用文件修改时间代替语义判断。找不到唯一对应任务时，只问需要继续哪一项。

## 初始化与已有项目接入

独立 `init` 可以先建立秩序，暂时没有任何任务。默认任务位置 projects/，也可用 --tasks-dir 指定已有约定下的相对目录。初始化不创建空 tasks、memory、playbooks 或 Inbox 文件夹。

- 空目录：生成简短 AGENTS.md、WORKSPACE.md 与实例标记。
- 已有项目：显式 init 会保留 AGENTS.md、CLAUDE.md、README.md 和现有文件，只补 WORKSPACE.md 与标记；不会自动修改宿主规则来强制加载本 Skill。Agent 需主动读新增入口；要长期接入时按用户已有授权在原入口增加一个链接即可。
- WORKSPACE.md 已被占用或约定不允许增加文件：沿用原组织，或在允许的子目录建立 TaskKit；不覆盖同名文件。
- new 不自动接管非空外来目录。已有授权要接入项目时由 Agent 先执行 init，无需额外发明审批步骤。
- 老 TaskKit 实例默认 projects/，继续原入口；不自动补写或迁移用户文件。

任务列表由 task 文件和交接记录实时派生，不再维护另一份可漂移的状态表。未登记的旧任务目录显示提示，回到其原 README 接续；本脚本不批量转换它们。

## 文件按需生长

通用任务起步只有 README.md（导航）、request.md（任务框架）、task.json（类型与版本）。需要资料时建立 inputs/，需要保留计算或运行结果时建立 outputs/，有成果时建立 deliverables/。探索脚本和缓存放 tmp/，可复跑所需输入不能只留在临时区。

需要追溯时补 sources.md，需要长期判断时补 findings.md，发生范围变化时在 events.md 留原因、旧范围和新范围。分阶段工作在同一任务内用不同文件或子目录，不重复嵌套一套工作区。已交付版本和关键证据保留；草稿可正常修订。

有既定 src/docs、data/output 或日期目录的项目按原约定交付，任务中记路径、版本和检查证据，代码仍在原仓库修改。交接脚本只校验任务内引用；原位交付可保存交付说明和实际检查日志，不复制一套源码，不声称已校验外部文件内容。

个人偏好需要时写 memory/profile.md，可复用入口进 memory/assets.md，成熟个人方法放 playbooks.local/。记录依据、适用范围和失效条件；用户确认的偏好可以直接更新，一次任务的发现不能自动当成普遍事实。流程故障与工具缺口进 Inbox/issues/，业务疑问留任务内；不自动上传。

## 收尾与续做

在阶段结束、阻塞或交付时用 checkpoint 保存交接：当前状态、已完成内容、下一动作、阻塞及解除条件、交付物、实际检查。快照追加写入 handoffs/，最新编号是当前入口；不再另维护一份相互竞争的状态库。README 保持导航，可追加背景但不冒充快照的当前状态。

续做先读最新快照与任务定义，再按需读相关来源。handoff 检查失败时说明哪个文件变了，检查变更是否合理，再保存新快照；不能为恢复绿色而删旧证据。尚无快照的旧任务按原 README 和结果接续。

active/blocked/done 是执行者记录的工作状态；done 需要交付文件和实查说明，脚本只保证这些字段和文件指纹完整。验收结果仍由任务流程给出；验证得到 FAIL 也可能是一项完整的验证交付，不能把“任务结束”偷换成“对象验证通过”。这里没有 hooks 或后台服务，不保证 Agent 在未调用脚本时也被强制约束。
