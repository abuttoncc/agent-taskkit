# API 验证场景卡

适用：新接口/SDK 能力核验、只读联调、响应契约验证。先问清用户需要哪一层结果；用户只要一个调用示例时不强制建立全套档案。

## 从问题生成清单

| 需要确认 | 要找的证据 | 常见反证 |
|---|---|---|
| 能否调用 | 官方文档版本、端点/方法、脱敏请求与响应 | HTTP 200 但业务码失败；网关成功但上游失败 |
| 是否返回所需数据 | 行数、字段、单位、日期、空值、用户指定对象 | 空数组；测试数据；错账号、币种或时间区间 |
| 覆盖是否完整 | 分页终止条件、去重键、已知有限清单或权限边界 | 只读第一页就宣布全量；重复行凑够数量 |
| 错误如何处理 | 授权范围内的无效参数/过期凭证案例与错误响应 | 自动重试掩盖首个错误；把超时当作功能不存在 |
| 能否复用 | 依赖版本、最小脚本、环境变量名、一次复跑记录 | 凭证或本机绝对路径写死；只给片段却宣称可运行 |

按本轮需求选行，别把表中所有项目自动变成 required。负向用例、限流压力、收费和有副作用请求仅在已授权范围执行；达到 spec 中的次数、时长或资源上限即保存状态，避免无限重试。

最小 CSV 示例（需按任务真实合同改写）：

```csv
id,requirement,description,basis,acceptance
response-schema,required,核验指定查询的响应字段,用户要求返回 id 与 value,业务码成功且每行包含 id 和数值型 value
pagination,investigate,查明分页边界,本轮总体尚不明确,说明是否分页并保存依据；若分页则验证终止规则
```

一次发现不支持分页可以是第二项调查的有效 PASS；第一项要求数据具备某字段，字段缺失就仍是 FAIL。用断言/领域脚本判断字段与业务意义，公共比较器只对账。

交付表包含检查 ID、承诺、观察状态、证据层级、证据路径、限制。注明“文档声称”与“实际响应”，报告空结果及缺项。稳定用法可另收为 Skill，但初版不自动发布或上传。
