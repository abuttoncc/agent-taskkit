# 通用任务框架

适用于需要留存的资料整理、方案设计、文档制作或工程任务。专门流程匹配时使用该流程；通用框架负责承接目标和交接，具体工作仍使用环境中合适的工具与 Skill。

先按 [工作区秩序](workspace.md) 判断直接做、续做还是新建。新建由 Agent 填 request.md：

1. **目标**：用户要获得什么结果，谁会使用它。
2. **范围与约束**：本轮边界、现有目录、已获授权与影响结果的假设；不把当前例子扩为普遍要求。
3. **材料与方法**：哪些输入已存在，哪些可从历史任务或个人方法复用，关键缺口是什么。
4. **执行与交付**：完成目标的最短步骤，交付位置与格式。简单任务一两句足够，不另堆计划文档。
5. **完成与停止条件**：怎样用实际结果确认完成；哪些证据足以停止扩查；未决项怎样交接。

只有缺口会改变结果或授权时才提问，其余写明合理假设并继续。用户纠正目标后更新 request，保留仍有效的工作；范围变更写 events.md，不删除原承诺来伪装完成。若需要更复杂方法，直接引用相关场景卡或已有 Skill；不为更换方法重建任务。

输入、运行结果、成品按需落盘。来源记录写清出处和定位；自己的推导区分输入、方法和判断。交付前按任务自己的完成条件做实际检查：文件能打开、代码行为符合目标、数字可追溯等；不要用文件数量或勾选代替验收。

按 [执行手册](operations.md) 留交接，再给用户结论、交付入口、必要限制和下一步。没有实际阻塞不把任务标 blocked。回答本身是成果时可存 deliverables/answer.md；在原代码仓交付时保存含路径、提交/差异位置和检查结果的交付说明。快照的 review 写实际做过的检查，不能用“已通过”占位。

经验先留任务，只有确认可复用时才进入个人方法索引；不要为收尾新建知识库或把个人结论上传到公共 Skill。
