# 外部调研

任务结论依赖仓库以外、会过时的事实时使用。仓库里就能核对的实现，以及一次就能答完、不必建档的小问题，不走本页。

溯源和「没找到就写没找到」见 [五条红线](red-lines.md)。本页只规定何时调研、材料写到哪。

## 何时标「有」

填 request 时判断。下面任一成立，把材料一节单独一行的 `外部事实：无` 改成 `外部事实：有`，后面写上要核的问题：

- 答案取决于现在的产品、接口、文档、价格、新闻，或「外面有没有这种东西」
- 结论要用仓库外的数字、日期或原话
- 要把本仓库的实现和外部系统对照

只改本仓库代码或文档、外部背景不影响完成条件时，保持 `外部事实：无`。

## 怎么做

1. 先看仓库和任务里已有的材料，只把仍然要靠外部才能回答的问题列出来。每问要有不同的证据，不把同一问改写几遍。
2. 用当前环境里真实可用的检索去查：网页搜索、打开原文，需要时查 X。金融数字优先用环境里的数据技能，网页只作补充。本包不自带搜索引擎，也不要假装某次搜索已经覆盖了全部来源。
3. 关键数字和「现在怎样」打开原始页面核对，不停留在搜索摘要。训练知识截止之后的事，以这次打开的页面为准。
4. 题目宽，或各方说法冲突时，用并行子任务分头查，或使用环境里已有的 deep-research 一类工作流。收回来的材料核对后再写入来源。
5. 来源写入任务 `sources.md`。表头沿用：ID、来源/版本/日期、证据层级、本地证据、限制。每条至少有一个 http(s) 链接和抓取日期。打不开、互相矛盾或没有链接的，写进限制。
6. 事实、推断、缺失分开写。交付里的外部结论只使用 `sources.md` 中有链接的事实。done 的 review 写实际打开过什么。

`外部事实：有` 且要把任务标成 done 时，检查器确认 `sources.md` 非空，并且至少有一条 http(s) 链接。它不判断内容对不对。公司研究、财报、同业比较仍用 finance-research，不在这里另建一套。
